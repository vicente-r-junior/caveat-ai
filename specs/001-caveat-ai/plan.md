# Implementation Plan: Caveat AI

This plan resolves the technical "how" for the spec. It commits to a stack, an architecture, a testing strategy, and a sequencing of work as sprints. Tasks for each sprint are generated by `/speckit.tasks` at the start of that sprint, scoped to the sprint's file in `sprints/`.

## 1. Stack

| Layer | Choice | Rationale |
|---|---|---|
| Backend runtime | Python 3.11 + FastAPI | Mature ecosystem; async streaming for chat with minimal ceremony |
| Frontend | React 18 + Vite + TypeScript | Standard, fast iteration, no SSR needed for a localhost app |
| Styling | Tailwind CSS | Speeds up styling; design tokens in `design-tokens.md` |
| Inference | Ollama on localhost:11434 | One-line install on every supported OS; standard REST API |
| Primary model | `gemma4:31b-instruct-q4_K_M` | 128K context, prosumer GPU friendly |
| Fallback model | `gemma4:e4b-instruct` | For low-end hardware; same prompt contract |
| PDF parsing | `pypdf` | Simple text extraction; OCR explicitly out of scope |
| Word generation | `python-docx` | Native .docx |
| PDF generation | `weasyprint` | HTML → PDF, consistent typography |
| Storage | SQLite stdlib | Local-only, file-based, zero ops |
| Python deps | `uv` | Fast, modern |
| JS deps | `pnpm` | Fast, deterministic |
| Task runner | `just` | Cross-platform Makefile alternative |
| Unit tests | `pytest` (Py), `vitest` (JS) | Standard |
| E2E tests | `playwright` (frontend), `pytest+httpx` (backend API) | Real browser; mockable LLM |

We deliberately do not use: Tauri, Electron, LangChain, vector databases, any cloud SDK, RAG framework.

## 3. The analysis pipeline

Six stages, each testable in isolation:

1. **Parse** — `pypdf` extracts text, structures by detected sections. Reject if no text layer.
2. **Classify** — Short prompt to Gemma. Returns MSA/NDA/SaaS/Employment/Other.
3. **Load playbook** — Read `caveat/playbooks/{type}.json`.
4. **Analyze** — Main prompt. Returns structured JSON list of findings.
5. **Validate citations** — Exact substring match. Failed citations dropped. >30% failure → retry with stricter prompt; second failure surfaces a warning.
6. **Build client summary** — Second prompt over validated findings.

## 4. Chat implementation

Server-Sent Events stream tokens from Ollama. Context contains: system prompt enforcing citations, full text of every loaded document (up to 5) with `<<DOC: name>>` separators, conversation history. Token budget check (100K limit) implements FR-015. Citation tags are post-processed and validated by the same exact-substring rule.

## 5. Testing strategy — three layers

### Layer 1 — Unit tests (`pytest`, `vitest`)

Every pipeline stage gets a unit test. Every prompt template gets a smoke test. Every export format gets a generation test. Every React component with logic gets a render test.

Target: full unit suite under 10 seconds. **LLM is mocked** at the `ollama_client` boundary with deterministic canned responses. The real model runs only in E2E and demo.

### Layer 2 — Backend E2E (`pytest + httpx`)

Drives the FastAPI app through real HTTP. Uses real fixture PDFs. LLM still mocked at `ollama_client` boundary. Validates routing, error handling, citation validation, storage.

### Layer 3 — Frontend E2E (Playwright)

Drives a real browser against a running backend. Backend uses a "fake Ollama" — small HTTP server returning canned responses. Validates the full user flow.

**Critical test:** runs the full pipeline with `httpx`/`requests` monkey-patched to fail on any non-localhost URL. Asserts no failures across the suite. This enforces Constitution Principle I.

## 6. Subagents and division of labor

This project uses four Claude Code subagents (configured in `.claude/agents/`):

- **`backend-python`** — owns `apps/backend/`. Reads constitution before each backend task.
- **`frontend-react`** — owns `apps/frontend/`. Reads `design-tokens.md` and the prototype before creating any component.
- **`test-engineer`** — writes unit tests, E2E tests, and produces the manual scenarios for `sprint-N-validation.md`.
- **`code-reviewer`** — read-only. Reviews diffs at the end of each sprint, validates against constitution principles I, II, IV, VII.

The main agent owns planning, integration, and writing the validation file.

## 7. Sprint sequencing

Each sprint has its scope in `sprints/sprint-N.md`. At the start of a sprint, Claude Code runs `/speckit.tasks` scoped to that sprint's file plus the spec/plan, generating `specs/001-caveat-ai/tasks.md`. Tasks are then executed in order.

| # | File | Days | Goal | Stories |
|---|---|---|---|---|
| 0 | `sprint-0-setup.md` | 1 | Repo + tooling + first commit | — |
| 1 | `sprint-1-backend-slice.md` | 3 | `/api/analyze` returning real findings with validated citations | US1 (backend) |
| 2 | `sprint-2-frontend-slice.md` | 3 | Browser flow: upload → processing → findings | US1 (full) |
| 3 | `sprint-3-summary-source.md` | 2 | Client summary + Source viewer tabs | US2 |

| 6 | `sprint-6-demo-submission.md` | 1 | Demo video, dev.to post, submission | — |

Total: 16 days.

**Slip protection:** Sprints 5 and 6 cover P2 stories. If Sprint 4 runs over, P2 work compresses or drops.

## 8. Demo script (Sprint 6)

1. Open `localhost:8787`, show empty state with privacy strip
2. Drop 5 PDFs into upload zone
3. Cut to processing screen with pipeline visible
4. Land on Findings tab, scroll, accept one redline
5. Switch to Client summary tab
6. Switch to Chat tab, ask "which contract has the most aggressive limitation of liability?"
7. Ask follow-up "draft a more aggressive redline of acme §4.2"
8. Show terminal with `tcpdump` filtering non-localhost traffic — empty
9. Toggle Wi-Fi off, run another analysis
10. Click Export, generate Word memo, open it in Word

Target length: 2 minutes.

## 9. Risks and mitigations

| Risk | Likelihood | Mitigation |
|---|---|---|
| Gemma 4 31B Q4_K_M produces too many citation failures | Medium | Citation validator + retry; fall back to E4B during dev if too noisy |
| Inference latency on demo machine pushes over 60s | Medium | Beefy demo machine; honest stats in the post |
| Ollama Gemma 4 model name changes | Low | Pin a tag; test fresh-install before submission |
| Contest judges cannot run the project locally | High | Recorded video as primary demo; one-command install for those who try |
| A sprint runs over and the next slips | High | Validation file enforces "done"; if a sprint takes 50%+ longer, descope the next P2 sprint |

## 10. Out of plan (explicitly)

- No code signing of binaries
- No analytics or error reporting (forbidden by Constitution I)
