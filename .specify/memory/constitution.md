# Caveat AI — Constitution

These are the non-negotiable principles that govern every implementation decision in this project. Any plan, task, or code that violates them must be rejected and revised, regardless of convenience or shipping pressure.

## I. Local-only by construction

All inference, document parsing, OCR, and storage happen on the end user's machine. No telemetry, no analytics, no crash reports, no model fine-tuning data — nothing transmits to any external service.

The application MUST function identically with the network interface disabled. This is testable: a passing test suite includes runs in airplane mode, and any code path that would fail without network access is a bug.

The only exception is the initial model download from a public registry (e.g., Ollama library), which happens once at install time and never again.

## II. Citations are mandatory

Every factual claim the model makes about a contract MUST be accompanied by a literal quotation from the source document, with a clause reference (e.g., "§ 4.2"). Outputs without citations are rejected by the citation validator before reaching the user.

The validator works by exact substring match against the source text. If a quoted passage cannot be located verbatim in the source, the citation is invalid and the model output containing it must be discarded and regenerated with a more restrictive prompt.

This is the primary defense against hallucination. It is not optional.

## III. The model does not invent

Prompts MUST instruct the model to speak only about what is present in the loaded documents, not to introduce outside legal knowledge unless the user explicitly asks for it (e.g., "compare to industry norms").

When the model is asked to draft a redline, it generates a proposal grounded in the actual contract text, not a generic template. When the model is asked a question it cannot answer from the documents, it MUST say so plainly rather than guess.

## IV. Disclaimers are part of the product

Every generated output (technical analysis, client summary, exported memo) MUST carry a disclaimer making it explicit that:

- The output is generated by a tool, not a lawyer
- It is intended to support, not replace, attorney review
- The attorney remains responsible for the final work product

These disclaimers are non-removable from exports. The product is a junior associate, not a partner.

## V. The lawyer is always in the loop

Nothing the model produces is "final." Every finding can be edited, rejected, or rewritten by the user before it enters an export package. Every chat response can be challenged. Every redline can be adjusted.

The system MUST never auto-send, auto-file, or auto-commit anything to a destination outside the application. The lawyer presses the final button.

## VI. Honesty over polish

When the model is uncertain, it says so. When citation validation fails repeatedly, the system surfaces this rather than retrying silently. When a contract is too long for the context window, the system declines to analyze it as a single document rather than truncating.

We would rather ship a tool that says "I don't know" than one that lies confidently.

## VII. Performance budgets are real

The product targets working lawyers, not patient evaluators. Analysis of a 30-page contract on recommended hardware MUST complete in under 60 seconds. Chat responses MUST begin streaming within 5 seconds of the user pressing enter.

If a feature can only be implemented by violating these budgets, it is reconsidered or cut.

## VIII. The Gemma 4 model choice is intentional

This project uses Gemma 4 31B Dense (quantized Q4_K_M) as its primary model, with a fallback to Gemma 4 E4B for hardware that cannot accommodate the larger model. The choice is justified by:

- The 128K context window, which allows entire contracts and multi-document comparisons in a single pass without retrieval-augmented complexity
- Strong reasoning quality in English at a size that can run on prosumer hardware
- An open-weights model that can be shipped and run locally without per-call licensing

We do not call hosted Gemini, OpenAI, or Anthropic APIs. The whole point of the product is defeated if we do.

## IX. The MVP is US-only, English-only

The MVP targets transactional lawyers practicing in the United States, working in English, on contracts governed by US state or federal law. We do not promise behavior on UK, Canadian, Australian, or any civil-law jurisdiction's contracts. We do not promise behavior on documents in any language other than English.

This is a focus decision, not a permanent limitation. Other jurisdictions may follow, but only after the US version is solid.

## X. Each sprint must be independently verifiable

Work is delivered in discrete sprints, each documented in `sprints/sprint-N.md`. A sprint is not "done" until all of the following exist:

1. **The implementation** — code that delivers the sprint's goal
2. **Unit tests** — covering the new logic, fast (full unit suite under 10 seconds), and runnable via `just check`
3. **End-to-end tests** — covering at least one happy path of the new functionality, runnable via `just test-e2e`
4. **A validation file** at `sprints/sprint-N-validation.md` containing:
   - Summary of what changed
   - List of unit tests added and what they cover
   - List of E2E tests added and what they cover
   - **Numbered manual validation scenarios** the human will execute, each with explicit expected behavior
   - The exact commands the human runs (`just verify-sprint-N`)
5. **Working slice** — even partial sprints must leave the codebase in a runnable state. Tests can be against mocked Gemma responses; that is acceptable. What is not acceptable is leaving the app broken between sprints.

A sprint without a validation file is not done. Skipping the validation file to "save time" is not negotiable. The validation file is the gate the human reviewer uses to decide whether to commit and proceed to the next sprint.

If a sprint task cannot be completed for legitimate technical reasons (e.g., a library doesn't behave as expected), document it in the validation file with what was tried and what's blocked. Do not silently skip.
